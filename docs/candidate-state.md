# 事件候选状态

## 状态和导出选择

- `detected`：已检测但尚未作人工结论；保留供后续扩展，当前默认流程主要使用以下三种状态。
- `confirmed`：边界和字段已确认；有效时可以导出。
- `needs-review`：边界、共享上下文或字段需要人工检查。
- `ignored`：明确忽略，强制 `selectedForExport=false`，不参与单项或批量导出。
- `selectedForExport`：独立复选状态；只有未忽略、已勾选且全部校验通过的候选才能进入批量生成器。

确认候选会勾选它，但不会绕过导出校验。全选可能包含无效候选，此时批量下载被阻止；“只选有效”按 `validateEvent` 重新选择。

## 手工修改保护

修改任何候选字段会把字段 `manuallyEdited` 和候选 `manuallyEdited` 设为 true。普通渲染不会重建草稿。

- 重新解析并保留修改：按当前 `CandidateSegment` 再调用单事件解析器，只覆盖自动字段；手工字段、状态和导出选择保留。
- 全部重新解析：按当前边界重新解析并重置手工字段、确认状态和默认选择。
- 重新检测事件边界：重新分段；只有稳定候选 ID、原始区间和原文全部相同才迁移状态及手工字段，避免把修改套到别的重复文字候选。

## 合并和撤销

只能合并相邻候选。新片段从第一个候选开始到第二个候选结束，包含中间换行、标记或分隔符，边界原因是 `manual-merge`，`mergedFrom` 记录原候选 ID，并重新调用 `parseEventText`。被合并的旧候选从当前列表移除，避免重复导出。应用保存最近一次完整结果快照，可无损撤销一次合并。

## OCR 和模式切换

OCR 块校对不会自动覆盖候选，用户必须再次解析。重新识别、更换或删除图片会清除候选、活动字段和合并历史，因为新 `combinedText` 的索引空间不再等同旧文档。文字/图片标签和自动/单事件/多事件下拉框本身不会清空输入或 OCR 文档。

单事件模式继续使用一个 `EventDraft`；自动模式发现两个以上候选时进入候选状态机；强制多事件模式即使只有一个候选也展示候选卡片。
