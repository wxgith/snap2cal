# 排班表状态与失效规则

排班状态只存在当前页面内存，按依赖方向失效，用户手工修改不会被无关刷新静默覆盖：

- 换图或删图：取消旧 OCR/网格任务，释放旧图片 URL，并清除网格、映射、班次定义、assignment、occurrence 和排除项。
- 重做 OCR：取消旧任务，清除网格及下游语义；已有班次定义可保留，但必须在新网格确认后重新映射代码。
- 移动、新增、删除或恢复网格线：重新分配 OCR 块，网格回到未确认，清除人员/日期确认、occurrence 和排除项；班次定义保留。
- 修改日期/人员区域：重新设置 `RosterCell` 角色，清除日期、人员、assignment 生成结果、occurrence 和排除项。
- 修改年份或月份：重新解析未手工修改的日期列，保留手工日期，清除旧 occurrence 排除 ID；不读取当前年月。
- 修改人员：保留来源格和 OCR 原文，立即重建 assignment/occurrence；重复姓名仍保持独立人员，不自动合并。
- 修改班次定义：定义立即变为未确认，重新校验并重建受影响 occurrence；同一 assignment、定义 ID 和日期的稳定 occurrence ID 可保留单次排除。
- 修改 assignment：只更新可编辑代码与 `manuallyEdited`，保留 `originalText`、OCR 块和来源格；新代码重新精确映射，定义 ID 改变时不会错误继承旧 occurrence 排除。
- 排除单次 occurrence：只在内存集合保存稳定 ID，不删除原 assignment；重新勾选可恢复。
- 模式切换：已加载工作区保持挂载但隐藏，当前内存状态安全保留；刷新或关闭页面全部清除。

无效、低置信度或未映射结果始终显示提示。重新检测或结构变化不会把旧手工状态迁移到不再对应的格；人员选择、团队标题开关、时区和提醒设置只影响当前内存中的生成与导出。
