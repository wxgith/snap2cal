# 多事件候选检测

## 入口和数据流

单事件入口 `parseEventText(input, options): EventDraft` 保持不变。多事件入口为：

```ts
parseEventCandidates(input, options): MultiEventExtractionResult
```

数据流是：原始文字 → `segmentEventText` → `CandidateSegment` → 共享上下文虚拟输入 → 原 `parseEventText` → 来源映射 → `EventCandidate` → 重复检查。分段器只判断边界，不复制日期、时间、地点或标题规则，也不知道 OCR 坐标。

## 边界优先级

1. 显式 `活动一`、`事件1` 标签；
2. 编号项：`1.`、`1、`、`（1）`、`(1)`、`一、`；
3. 项目符号：`-`、`*`、`•`、`·`；
4. 空行分隔的多行事件组；
5. 以日期开头且自身包含时间/全天与标题的完整事件行；
6. 共享日期下以时间开头的事件行；
7. 分号各侧均有完整事件结构时的弱边界；
8. 其余含日期或时间的整段使用单事件回退。

普通说明或尾注不会因单独成行就成为候选，而是进入未分配文字区。最多生成 50 个候选；溢出内容仍保留为未分配文字，并产生 `CANDIDATE_LIMIT_REACHED`。

## 共享日期和地点

纯日期行或“日期：…”行仅在后续至少有两个时间事件行时成为共享日期。`8月26日 地点：公司三楼` 可同时建立共享日期和地点。日期传播在新日期或明确章节标题处停止；地点传播到新地点或章节边界。候选自身的显式日期/地点永远优先。

共享值通过虚拟文本交给 `parseEventText`，随后按虚拟片段表把字段来源映射到真实标题行。不会重新搜索共享文字。

## SourceSpan 和索引

原始输入不统一换行、不执行 Unicode code point 重编号。所有开始/结束位置均为 JavaScript UTF-16 半开区间 `[startIndex,endIndex)`，CRLF 占两个 code unit，emoji 依 JavaScript 字符串长度计数。候选 ID 由原始区间、文本哈希和顺序确定；重复文字通过区间区分。

## 候选置信度与重复项

候选置信度描述边界可靠性，和 `ExtractedField.confidence`、OCR 0–1 置信度分开。明确列表或完整日期行且校验有效通常为高；共享上下文、空行或分号边界通常为中；缺少必要字段为低。高置信度有效候选默认确认并选中，中置信度有效候选默认待确认但可选中，低置信度候选默认不选。

重复检查只在日期、时间和规范化标题相同、地点不冲突时提示 `DUPLICATE_EVENT_CANDIDATE`。候选不会自动删除或合并。

## 未分配文字和能力边界

共享标题、章节标题、尾注、纯说明和候选上限溢出内容都保留 `SourceSpan`。用户可把片段追加到指定候选备注。

当前不支持复杂海报、多栏排版、二维课程表、排班表、同上/省略/代词、跨多日行程、重复规则或一张图中多个遥远区域；这些结构可能导致边界或共享上下文误判。
