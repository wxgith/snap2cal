# Support

Choose the smallest public report that can reproduce the issue, and use synthetic data only.

## Bug

Use the bug report form for repeatable application behavior, browser errors, failed downloads, or regressions. Include version, mode, browser, operating system, steps, expected result, and actual result.

## OCR accuracy

Use the OCR problem form for misread printed text, image normalization, evidence boxes, or Worker failures. Prefer a newly created synthetic image. A minimal, cropped, fully redacted sample is acceptable only when synthetic reproduction is impossible.

## Feature request

Use the feature request form to describe the underlying problem, current workaround, why the existing four modes do not solve it, privacy/network implications, and whether you can contribute a synthetic test fixture. The roadmap is not a delivery commitment.

## Usage question

Read the two READMEs and architecture documents first. A public Issue may be used for a concise usage question that contains no personal or internal information.

## Security or privacy vulnerability

Do not use a public Issue. Follow [`SECURITY.md`](SECURITY.md). An ordinary question about the documented memory-only behavior may be public, but suspected data exposure or third-party transmission must be reported privately.

## Unsupported inputs

PDF, Excel, CSV, batches, HEIC, TIFF, GIF, SVG, accounts, cloud synchronization, payroll, attendance, and legal compliance analysis are not supported. Handwriting, borderless or heavily decorated tables, multiple shifts in one cell, and unusual merged layouts may be unsuitable for current OCR and grid recognition.

Do not submit a real schedule, course timetable, employee roster, private chat, phone number, email address, exact address, employer/school internal information, logo, portrait, access token, or other unredacted data in any public channel.
